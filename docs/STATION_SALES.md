# Продажи сайта и агентов по станциям

Отдельный отчёт АИС `/station-sales` — таблица «Сводный отчёт по продажам с
сайта Автовокзал57.рф и агентами в разрезе станций» из `htdocs/ais/in.php`.
Сохранены все 20 колонок, их порядок, итоги и условия расчёта по станциям.
Сайт читается из нового Postgres `avtovokzal`, копия продаж станций хранится
в Postgres `ais`. При формировании отчёта подключения к Firebird нет.

## Как пользоваться

Период сверху — период отчёта. Фильтр станции ограничивает строки и итоги
отчёта. Блок «Данные автостанций» изначально свёрнут. В заголовке видны
общий статус и наиболее ранняя актуальность среди активных станций. Если
хотя бы одна ещё не собрана, общая актуальность неизвестна. Ошибка любой
станции в её последнем задании имеет приоритет в общем статусе.

Раскройте блок для выбора режима и периода. Кнопка «Обновить» в строке
запускает одну станцию. Для группового запуска отметьте станции и нажмите
«Обновить выбранные станции». Незавершённое задание той же станции второй
раз не создаётся. Можно закрыть вкладку: сбор продолжится.
Открытая страница показывает прогресс и обновляет уже сформированный отчёт
после публикации периода.

В АИС на странице «Настройки» задаются время ежедневного сбора (по умолчанию
07:00 по часам сервера АИС), выключатель автоматического запуска и число
календарных дней в окне (1–3650, по умолчанию 90). Сегодня входит
в это число. При запуске 19 ноября окно по умолчанию охватывает 22 августа — 19 ноября.
Для глубины используется существующий ключ `station_sales_lookback_days`.
Сохранённое ранее число имеет приоритет над новым значением по умолчанию.

Кнопка «Обновить» использует то же окно и работает при выключенной
автоматике. Изменения настроек относятся к новым заданиям. Уже поставленные
задания продолжают обработку своего периода.

Флажок «Указать свой период продаж» позволяет пересчитать архив. Это даты
**операций продажи/возврата SALE.DATESALE**, а не даты поездки. Для ведомости
за выбранный месяц могут потребоваться билеты, проданные раньше месяца.
Если в периоде есть возврат, сбор также сверяет связанную с ним исходную продажу за любую дату.

По каждой станции видны:

- актуальность последнего полностью собранного текущего окна и его границы;
- последний успешно пересчитанный период, в том числе архивный, и время завершения;
- состояние последнего задания, число дней в выборке, число загруженных строк и ошибка.

Актуальность — московское время **начала** успешного сбора периода. Пересчёт прошлого периода и прерванное обновление эту отметку не
двигают. После увеличения глубины или смены дня прежняя отметка остаётся
видимой, а страница сообщает, что новое окно ещё не собрано полностью.

## Устойчивость сбора

`station-sales:sync` создаёт задания в `station_sales_sync_runs`, а
`station-sales:work` обрабатывает их порциями. Ofelia каждую минуту вызывает
`station-sales:sync --scheduled`. Команда читает настройки и ставит задания
при совпадении часов и минут. Дата автозапуска хранится отдельно для каждой
станции. Обработчик очереди также запускается каждую минуту. Одна станция может иметь одно
незавершённое задание; проверка защищена блокировкой строки состояния.

Настройка «Дней в порции загрузки продаж станций» принимает от 1 до 90 дней,
по умолчанию 10. Размер порции фиксируется при постановке задания.
Сбор читает окно от новых дат к старым. На каждую порцию приходится один
запрос Firebird без ограничения числа строк. Дополнительные даты досылок
группируются в порции того же размера.

Отдельный PHP CLI-процесс с лимитом памяти 128 МБ читает строки во временный
файл с дедлайном 25 секунд. Обработчик переносит файл в
`station_sales_staging` небольшими группами. После последней порции он
публикует период станции в одной транзакции. Все поля исходной строки
сохраняются в `raw_data`. Глобальный ключ из восьми полей соответствует
первичному ключу `SALE_ALL` и исключает дубликаты.

При временном сбое обработчик повторяет ту же порцию через минуту. После
трёх последовательных ошибок задание завершается с ошибкой. Отчёт до
публикации показывает предыдущие данные. Прогресс по датам и срок захвата
задания сохраняются в БД, поэтому сбор продолжается после перезапуска.
При переходе со строковой пагинации незавершённое задание перечитывает
свой период календарными порциями.

## Возвраты и исходные продажи

В этой сводной `TICK_BACK` используется в двух суммах по дате поездки —
«в ведомости» для сайта и агентов — и влияет на их общий итог.
Агентские возвраты считаются по собственным строкам с `TYPE_OPER > 0`.

В локальной BUSTER триггер `SALE_BACK_TICK` помечает исходный билет при
`TYPE_OPER IN (1,4,5,6)`, `KKM_OK=1` и `COMMENT_TICK<>8`. Поиск идёт
по `N_TICKET` и `DOB_N_TICKET` (индекс `NOM_TICK`), отдельно для билетов
с открытой датой `1899-12-30` и обычных. Триггер видит операции всех касс.

Сверка всех 14 239 исходных продаж кодов 9984, 9999 и 9900 на локальной
копии станции дала 1 761 продажу с подходящим возвратом. Сохранённый флаг
совпал во всех строках. Среди операций 2025–2026 годов был возврат через
106 дней после продажи. В локальной объединённой таблице АИС по той же
проверке внутри одной `source_station` нашлись пары у 92 161 из 93 496
помеченных продаж и у одной продажи с нулевым флагом. Отсутствие пары в
копии само по себе ничего не говорит о наличии возврата на станции.
В legacy есть и отдельный путь: ручная пометка в `htdocs/ais/ksrwork/index.php`
обновляет `SALE.TICK_BACK` и создаёт запись в `KSR_BACK`.

В выборку входят операции за указанные даты и исходные продажи по их
возвратам, включая возвраты в другой кассе. Сбор читает фактический
`TICK_BACK` исходной строки. При публикации продажи за выбранные даты
заменяются актуальными строками из базы станции.

**Досылки из «Возвратов без станции».** При сборе текущего окна АИС читает
подтверждённые досылки из `refunds` сайта и определяет станцию по заказу.
Сверяется день аннулирования. Если станция перенесла дату в SALE, проверяется
также день возврата денег и, если он отличается, день создания возврата
(он используется при досылке до выплаты). Задание включает затронутые
архивные сутки сверх обычного окна. Для явно указанного периода сохраняются
выбранные границы. Источником станционных строк и сумм остаётся SALE.

Список досылок фиксируется при запуске. АИС отмечает обработанные досылки
отдельно для каждых суток в транзакции публикации всего периода. Ошибка станции
оставляет дату для следующего запуска. Новая досылка по той же дате,
включая поступившую во время сбора, снова ставит её на сверку.
Пока билет только ожидает досылки, он не создаёт станционный возврат.

Сверка также охватывает другие записи, внесённые задним числом в выбранное окно.
Для обработки операции, дата которой оказалась вне окна после длительного
перерыва, укажите её период вручную.

## Расчёты

Продажи сайта считаются по `orders.total_price` оформленных заказов, что
сохраняет страхование старых заказов. Для импортированных заказов
сохраняется исходное условие `legacy.status = 1`. Возвраты учитываются по
фактическому возврату денег; их исходная стоимость включает страхование
из `refunds.legacy.strah`. Отдельные возвраты багажа учитываются своей
стоимостью, возвраты удержаний уменьшают КРЗ без повторного вычитания
стоимости билета. Ведомость сайта считает поездки и стоимость возвращённых
билетов по датам поездки; предварительная продажа — поездки после конца
отчётного периода, оплаченные в этом периоде.

Условия станционных колонок сохранены из исходника:

| Показатель | Условие |
| --- | --- |
| Ведомость сайта по базе станции | `AWTCODSALE=9984`, дата поездки в периоде, `TYPE_OPER=0`, `TICK_BACK=0` |
| Агентские в ведомости | то же, `AWTCODSALE IN (9999,9900)` |
| Агентские продано | дата продажи в периоде, `TYPE_OPER=0`, `KKM_OK=1` |
| Агентские возврат | дата продажи в периоде, `TYPE_OPER>0`, сумма `PRICE_PLACE+PRICE_BAG` |
| Агентские стоимость возвращённых | **только `PRICE_PL_ISX`**, как исходный `AGENTBACK`, без `PRICE_BAG_ISX` |
| Агентские КРЗ | стоимость возвращённых минус сумма возврата |
| Агентские предварительные продажи | агентские продажи, дата поездки после периода |
| Агентские возврат предварительных | дата операции в периоде, поездка после периода, `TYPE_OPER>0`, сумма `PRICE_PL_ISX+PRICE_BAG_ISX` |

Не добавлялись отсутствующие в legacy фильтры `IS_PRN`, `MAY_BACK`,
`TYPE_TICK` и т. п.: они изменили бы суммы. Денежные производные показатели
и итоги складываются в целых копейках.

## Выкладка и перенос архива

После выкладки кода нужны миграция АИС, сборка SPA и перечитывание заданий:

```bash
docker compose exec -T ais_app php artisan migrate --force
docker compose run --rm --no-deps ais_spa sh -lc 'npm install && npm run build'
docker compose restart ais_spa scheduler
```

Новый отчёт автоматически доступен системным администраторам. Для других
ролей выдаются `report:station-sales.view` и, отдельно, право
`report:station-sales.refresh`. Обновление не требует кода подтверждения,
из сессии «от имени сотрудника» запуск запрещён сервером.

Для начального переноса прежнего `SALE_ALL`:

```bash
docker compose exec -T ais_app php artisan station-sales:import-legacy
```

По умолчанию читается локальная Firebird `firebird:ais`. Для другой копии
задайте в `ais-api/.env` переменные `LEGACY_AIS_DB_HOST`,
`LEGACY_AIS_DB_PORT`, `LEGACY_AIS_DB_NAME`, `LEGACY_AIS_DB_USER`,
`LEGACY_AIS_DB_PASSWORD`. Команда читает архив по 1000 строк дочерними
процессами с тем же дедлайном, сохраняет курсор в `storage/app` после каждой
порции и продолжает с него при повторном запуске. `--pages=10` ограничит
число порций одного запуска; `--restart` перечитает источник с начала.
Существующие строки не перезаписываются, поэтому архив не затирает данные,
которые уже собраны с живой станции. Импорт не выставляет актуальность
станций. Исходная Firebird остаётся без изменений.

Ручной запуск очереди и обработчика:

```bash
docker compose exec -T ais_app php artisan station-sales:sync --stations=5701,5706
docker compose exec -T ais_app php artisan station-sales:sync --mode=full --stations=5706 --from=2026-10-01 --to=2026-10-31
docker compose exec -T ais_app php artisan station-sales:work
```

Проверки: `docker compose exec -T ais_app php artisan test --compact --filter=StationSales`
проверяет формулы, настройки, выбор станций, сохранение актуальности,
атомарную публикацию, повторный сбор, возобновление после обрыва, права и
реальное прерывание зависшего дочернего процесса.

Дополнительная сверка всех 19 денежных колонок с оригинальными запросами
Firebird (нужны перенесённый архив и обе прежние базы `site`/`ais`):

```bash
docker compose exec -T ais_app php tests/Integration/compare-station-sales-legacy.php 2026-06-01 2026-06-30
```

На локальной копии за июнь 2026 проверено 38 показателей по двум
настроенным станциям, расхождений нет. Перенесено 968 082 строки архива.
